## Codebase Patterns
- Next.js 16 instrumentation hook (`src/instrumentation.ts`) runs before the server accepts traffic — use it for fail-closed config checks
- Environment validation is in `src/lib/env.ts` with `validateEnv()` (returns issues) and `assertEnvOrExit()` (exits process in prod, warns in dev)
- DB adapter pattern: `src/lib/db/adapter.ts` interface, `sqlite.ts` and `postgresql.ts` implementations, `index.ts` selects based on `DB_TYPE`
- In production (`NODE_ENV=production`): DB init rejects instead of catching errors; auto-seed is skipped entirely
- `dbReady` export in `src/lib/db/index.ts` is a Promise — await it in readiness checks
- Health endpoint at `src/app/api/health/route.ts` returns 200/503 based on `dbReady` status
- SQLiteAdapter runs migrations in the constructor (sync), PostgreSQLAdapter runs migrations in initialize() (async) — both fail-closed in prod
- Quality commands: `pnpm type-check`, `pnpm test`, `pnpm lint` — but if `node_modules/.bin` is missing, run via `node node_modules/.pnpm/<pkg>/node_modules/<pkg>/<entry>`
- `process.env.NODE_ENV` is read-only in TypeScript types — use `Object.assign(process.env, { NODE_ENV: ... })` in tests
- `vi.hoisted()` is required for mock functions referenced inside `vi.mock()` factories
- Many pre-existing `@typescript-eslint/no-explicit-any` errors throughout the codebase — not introduced by new changes
- Schema is split across files: `schema.ts` (SQLite core + re-exports), `schema-interview.ts` (SQLite interview tables), `schema-commercial.ts` (SQLite org/membership tables), `pg-schema.ts` (PostgreSQL production source with ALL tables in one file)
- Pattern for new entity groups: create `schema-<domain>.ts` for SQLite, import `users` from `./schema`, re-export from `schema.ts`; add equivalent PG tables to `pg-schema.ts`
- Vitest binary location: `node_modules/.pnpm/vitest@4.1.8_@opentelemetry_cf5557e02b4b3a36d0231881803c600e/node_modules/vitest/dist/cli.js`
- Drizzle-kit binary location: `node_modules/.pnpm/drizzle-kit@0.31.9/node_modules/drizzle-kit/bin.cjs`
- TypeScript binary location: `node_modules/.pnpm/typescript@5.9.3/node_modules/typescript/bin/tsc`
- PGlite (`@electric-sql/pglite`) provides real PostgreSQL 18.3 via WASM — use `drizzle-orm/pglite` driver + migrator for integration tests without Docker/server; startup takes ~3-4s per instance, use `vi.setConfig({ testTimeout: 30000 })`
- PGlite query typing: `pg.query<T>` infers T as `unknown` without explicit annotation — always pass type parameter or use a typed helper

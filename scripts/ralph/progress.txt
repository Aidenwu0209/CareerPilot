## Codebase Patterns
- Next.js 16 instrumentation hook (`src/instrumentation.ts`) runs before the server accepts traffic — use it for fail-closed config checks
- Environment validation is in `src/lib/env.ts` with `validateEnv()` (returns issues) and `assertEnvOrExit()` (exits process in prod, warns in dev)
- DB adapter pattern: `src/lib/db/adapter.ts` interface, `sqlite.ts` and `postgresql.ts` implementations, `index.ts` selects based on `DB_TYPE`
- In production (`NODE_ENV=production`): DB init rejects instead of catching errors; auto-seed is skipped entirely
- `dbReady` export in `src/lib/db/index.ts` is a Promise — await it in readiness checks
- Health endpoint at `src/app/api/health/route.ts` returns 200/503 based on `dbReady` status
- SQLiteAdapter runs migrations in the constructor (sync), PostgreSQLAdapter runs migrations in initialize() (async) — both fail-closed in prod
- Quality commands: `pnpm type-check`, `pnpm test`, `pnpm lint` — but if `node_modules/.bin` is missing, run via `node node_modules/.pnpm/<pkg>/node_modules/<pkg>/<entry>`
- `process.env.NODE_ENV` is read-only in TypeScript types — use `Object.assign(process.env, { NODE_ENV: ... })` in tests
- `vi.hoisted()` is required for mock functions referenced inside `vi.mock()` factories
- Many pre-existing `@typescript-eslint/no-explicit-any` errors throughout the codebase — not introduced by new changes
- Schema is split across files: `schema.ts` (SQLite core + re-exports), `schema-interview.ts` (SQLite interview tables), `schema-commercial.ts` (SQLite org/membership tables), `pg-schema.ts` (PostgreSQL production source with ALL tables in one file)
- Pattern for new entity groups: create `schema-<domain>.ts` for SQLite, import `users` from `./schema`, re-export from `schema.ts`; add equivalent PG tables to `pg-schema.ts`
- Vitest binary location: `node_modules/.pnpm/vitest@4.1.8_@opentelemetry_cf5557e02b4b3a36d0231881803c600e/node_modules/vitest/dist/cli.js`
- Drizzle-kit binary location: `node_modules/.pnpm/drizzle-kit@0.31.9/node_modules/drizzle-kit/bin.cjs`
- TypeScript binary location: `node_modules/.pnpm/typescript@5.9.3/node_modules/typescript/bin/tsc`
- PGlite (`@electric-sql/pglite`) provides real PostgreSQL 18.3 via WASM — use `drizzle-orm/pglite` driver + migrator for integration tests without Docker/server; startup takes ~3-4s per instance, use `vi.setConfig({ testTimeout: 30000 })`
- PGlite query typing: `pg.query<T>` infers T as `unknown` without explicit annotation — always pass type parameter or use a typed helper
- better-sqlite3 native `transaction()` does NOT support async callbacks — use synchronous callbacks with `tx.insert(table).values(obj).run()` (the `.run()` is required to actually execute SQL inside a sync transaction)
- Auth.js v5 config is at `src/lib/auth/config.ts` — jwt callback receives `user`/`account`/`profile` only on first sign-in call; `resolveOAuthAccount()` in `src/lib/auth/oauth-linking.ts` handles persistent account linking
- `@/lib/db` can be mocked in tests via `vi.mock()` with an async factory that creates a real in-memory SQLite DB — all consumers (repositories, services) get the test DB automatically
- ESLint binary location: `node_modules/.pnpm/eslint@9.39.2_jiti@2.6.1/node_modules/eslint/bin/eslint.js`
- NextAuth v5 `encode()` from `next-auth/jwt` can create session tokens manually: `encode({ token, secret, maxAge, salt })` — salt must match the cookie name (`authjs.session-token` or `__Secure-authjs.session-token` in production)
- Mail adapter pattern: `MailAdapter` interface with `TestMailAdapter` (in-memory, has `getLastCode(email)`), `ConsoleMailAdapter` (dev logging), `SmtpMailAdapter` (production, uses nodemailer dynamically); `getMailAdapter()` selects based on `NODE_ENV` and `SMTP_HOST`
- Session claims refresh: `src/lib/auth/session-claims.ts` provides `refreshUserClaims(userId)` (fetches platformRole + status from DB) and `shouldRefresh(lastRefreshAt)` (60s staleness check); JWT callback calls these periodically; sensitive ops should use `resolveUser()` which always reads from DB
- Middleware API auth: `src/middleware.ts` enforces session-cookie presence for ALL `/api/*` routes except `PUBLIC_API_PREFIXES` (`/api/auth`, `/api/health`, `/api/share`); returns `401 { error: 'AUTH_REQUIRED' }` for missing cookie
- Route inventory test at `src/app/api/route-inventory.test.ts` auto-discovers all API route.ts files and classifies them against `PUBLIC_API_PREFIXES` — new unclassified routes are visible in test output
- Rate limiting: `src/lib/rate-limit/rate-limit.ts` — `checkRateLimit(key, policy)` + `rateLimitedResponse(retryAfter)` + `RATE_LIMIT_POLICIES` constants; adapter pattern with `MemoryRateLimitAdapter` (default) and pluggable `setRateLimitAdapter()` for Redis/DB; `failClosed` policies deny on store-unavailable, `failClosed: false` allows
- SSRF guard: `src/lib/security/ssrf-guard.ts` — `validateUpstreamUrl(url)` checks HTTPS + approved domain allowlist; `sanitizeUpstreamUrl(url, fallback)` returns URL or fallback; `SSRF_SAFE_FETCH_OPTIONS` with `redirect:'error'`; approved domains: api.openai.com, api.anthropic.com, generativelanguage.googleapis.com
- Audit service: `src/lib/audit/audit-service.ts` — `recordAuditEvent()` is the single entry point for all audit events; auto-sanitizes summaries (rejects API keys, auth headers, JWT, multi-line doc text); idempotent dedup via `idempotent:true` + `requestId`; query via `queryAuditEvents()` (filter by actor/target/action/tenant/time); audit_events table is immutable (triggers block UPDATE/DELETE)

- AC4: `getProviderCredentialInfo()` returns masked credential (`sk••••••cdef`), version, and lastValidatedAt; never exposes plaintext
- AC5: Missing `AI_CREDENTIAL_MASTER_KEY` → `CredentialCryptoError` thrown; tampered ciphertext fails GCM auth tag verification; malformed blobs rejected
- 34 tests: key source (5), plaintext isolation (6), rotation (6), masked info (7), fail-closed (8), round-trip (3)
- Typecheck passes, all 861 tests pass (40 files)
- **未来迭代的学习：**
  - The `aiProviders` table already had `encryptedCredentials` and `credentialVersion` columns — no new table needed for US-032
  - `AI_CREDENTIAL_MASTER_KEY` is already validated in `src/lib/env.ts` with production checks (required, ≥32 chars, ≠ AUTH_SECRET)
  - AES-256-GCM provides authenticated encryption — tampered ciphertext fails at `decipher.final()` during auth tag verification
  - The `CredentialKeyAdapter` interface allows production KMS integration (AWS KMS, Vault) without changing application code

  - `maskCredential` shows first 2 and last 4 chars with bullets in between — no exact length leak for short keys (≤5 chars fully masked)
